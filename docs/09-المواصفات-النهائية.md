# مقدمة

هذه الوثيقة **مرجع جامع**. كل ما فيها مبني على قرارات مؤكدة، لا افتراضات. تسبقها ثماني وثائق تفصيلية:

| الوثيقة | المحتوى |
|---|---|
| `00` | هوية المشروع |
| `01` | تحليل سير العمل |
| `02` | الوحدات الرئيسية |
| `03` | صلاحيات المستخدمين |
| `04` | تجربة الاستخدام |
| `05` | نظام التصميم البصري + معاينة HTML |
| `06أ · 06ب · 06ج` | تصميم 25 شاشة و3 مطبوعات |
| `07` | مراجعة السيناريوهات |
| `08` | التفاصيل التقنية والتشغيلية |
| — | نموذج تفاعلي HTML |

# 1 · هوية النظام في ثلاثة أسطر

> نظام محلي لعيادة جراحة عامة، يعمل بلا إنترنت على جهازين، بواجهة عربية على نهج Apple.
> يديره طبيب وسكرتيرة بصلاحيات منفصلة تمامًا في الطبي، ومكشوفة تمامًا في المالي.
> يقيس نجاحه بمعيار واحد: **كم مرة نظر الطبيب إلى الشاشة بدل المريض.**

# 5 · معايير القبول

النظام يُعتبر ناجحًا إذا تحقق كل ما يلي. هذه ليست أمنيات — بل **اختبارات تُجرى**.

## 5.1 السرعة

| الاختبار | الحد |
|---|---|
| تسجيل زيارة ضماد كاملة | ≤ 10 ثوانٍ |
| إنهاء زيارة مراجعة مع وصفة وطباعة | ≤ 60 ثانية |
| تسجيل حضور مريض | ≤ 3 ثوانٍ |
| قبض مبلغ كامل | ≤ 5 ثوانٍ |
| إنشاء مريض جديد مع موعد | ≤ 20 ثانية |
| إقفال اليوم | ≤ 15 ثانية |
| فتح ملف مريض | ≤ 300 مللي ثانية |
| نتائج البحث أثناء الكتابة | ≤ 200 مللي ثانية |

## 5.2 النقرات

| المهمة | الحد |
|---|---|
| أي وظيفة مهمة | **≤ 3 نقرات** |
| قراءة ما قيل للمريض آخر مرة | **0 نقرة** |
| رؤية التحذيرات الطبية | **0 نقرة** |
| معرفة من ينتظر | **0 نقرة** |

## 5.3 الموثوقية

| الاختبار | المطلوب |
|---|---|
| قطع الكهرباء فجأة أثناء الكتابة | لا فقدان · لا تلف · العودة لنفس الحالة |
| فصل الراوتر أثناء الدوام | الجهازان يواصلان · مزامنة سليمة عند العودة |
| إطفاء جهاز والعمل على الآخر ساعة | مزامنة كاملة بلا تعارض عند العودة |
| استعادة من نسخة احتياطية | تعمل ومختبَرة قبل التسليم |
| إغلاق النظام أثناء زيارة مفتوحة | المسودة سليمة بالحرف |

## 5.4 التعلّم

| الاختبار | الحد |
|---|---|
| تدريب السكرتيرة | ≤ 30 دقيقة |
| تدريب الطبيب | ≤ 20 دقيقة |
| الدليل المطبوع | صفحتان |

**قاعدة القبول الحاكمة:** إن احتاج المستخدم أكثر من ذلك، فالتصميم فشل لا المستخدم.

## 5.5 السلامة الطبية

| المطلوب |
|---|
| التحذيرات الطبية ظاهرة قبل بدء الزيارة وأثناءها — لا تُطوى أبدًا |
| لا زيارة تُغلق بلا مبلغ محدد (ولو صفرًا) |
| لا معلّقة تُغلق بلا حدثها الحقيقي |
| كل تعديل على سجل طبي يحفظ النص الأصلي |
| السكرتيرة لا ترى حرفًا طبيًا واحدًا — شاشةً وورقًا |

# 7 · خطة الإصدارات المقترحة

**اقتراح للنقاش لا قرار.** الهدف: عيادة تعمل بأسرع ما يمكن، ثم تحسين.

## الإصدار 1 — «العيادة تعمل»

المرضى · المواعيد ولوحة اليوم · الزيارات ولوح الالتقاط · بطاقة الاختتام · الوصفات وطباعتها · القبض والديون · الصندوق والإقفال · البحث · الصلاحيات · التصميم البصري كاملًا.

> **معيار الإصدار:** يمكن إدارة يوم عمل كامل بلا ورق.

## الإصدار 2 — «النظام يتذكر»

المعلّقات · الحالات · الأعمال الجراحية · الطلبات الخارجية · اتصالات الغد · قائمة الانتظار · التواصل الداخلي · باقي المطبوعات.

> **معيار الإصدار:** لا يضيع مريض ولا التزام.

## الإصدار 3 — «الصورة الكاملة»

المرفقات ورمز QR · المصروفات · التقارير الثلاثة · سجل الأحداث · القوالب المتقدمة.

> **معيار الإصدار:** الطبيب يعرف حال عيادته بالأرقام.

## ⚠ ملاحظة معمارية حاسمة

**المزامنة والتشفير والمعرّفات الفريدة ليست ميزات تُؤجَّل** — هي أساس يُبنى من السطر الأول.

محرك المزامنة قد يُفعَّل في الإصدار 2، لكن **البنية التي تسمح به يجب أن توجد من البداية**. إضافتها لاحقًا تعني إعادة بناء لا إضافة.
